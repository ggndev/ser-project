# ☁️ Backend: Speech Emotion Recognition API

A small **FastAPI** service that receives a voice recording and returns the detected emotion. It runs the exported **ONNX** model with **ONNX Runtime on CPU only**: no PyTorch, no librosa, so it fits a 512 MB free cloud instance.

> Part of the [Speech Emotion Recognition project](../README.md). Line-by-line explanation: [docs/02-backend](../docs/02-backend/README.md).

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/` | Service info and the list of labels |
| `GET` | `/health` | Health check (`status`, model file, labels) |
| `POST` | `/predict` | Upload audio (multipart field `file`) and get the emotion |
| `GET` | `/docs` | Interactive Swagger page generated by FastAPI |

### `POST /predict`

```bash
curl -F "file=@sample.wav" http://localhost:8000/predict
```

Example response (values shortened):

```json
{
  "emotion": "happy",
  "confidence": 0.82,
  "probabilities": { "angry": 0.02, "disgust": 0.01, "fear": 0.03, "happy": 0.82, "neutral": 0.06, "sad": 0.02, "surprise": 0.04 },
  "windows": [
    { "start_s": 0.0, "speech": true, "emotion": "happy", "confidence": 0.85 },
    { "start_s": 1.5, "speech": true, "emotion": "happy", "confidence": 0.79 }
  ],
  "speech_detected": true,
  "latency_ms": 6400.0
}
```

If no speech is found, the response has `"emotion": null` and `"speech_detected": false`. Bad input returns `400` (empty or undecodable file) or `422` (missing `file` field).

## How it works

1. **Decode** the upload (`soundfile`) and resample to 16 kHz mono (`soxr`).
2. **Trim silence** with a NumPy implementation that matches `librosa.effects.trim`, so the server pre-processes audio exactly as in training.
3. **Slice** the audio into 3-second windows with 50 % overlap (at most `MAX_WINDOWS`).
4. **Gate** windows that are too quiet (energy threshold `MIN_RMS`).
5. **Classify** each window with ONNX Runtime, one window per model call to keep memory flat.
6. **Average** the window probabilities into one answer and return the per-window timeline.

## Model files

```
backend/
├── model/
│   ├── model.onnx      model that is served (int8)
│   └── labels.json     class order and pre-processing settings
└── model_cnn/          small CNN alternative (copy it over model/ to use it)
```

`labels.json` is the **contract** between training and serving: class order, sample rate, window length and silence-trim setting. The server reads it at start-up instead of hard-coding these values.

## Configuration (environment variables)

| Variable | Default | Meaning |
|---|---|---|
| `MODEL_DIR` | `./model` | Folder holding the model and `labels.json` |
| `MODEL_FILE` | `model.onnx` | Model file name inside `MODEL_DIR` |
| `MAX_SECONDS` | `20` | Longest audio that is processed |
| `MAX_WINDOWS` | `5` | Maximum windows classified per request |
| `MIN_RMS` | `0.003` | Energy gate for "no speech" |
| `ORT_THREADS` | `2` (`1` in the Docker image) | ONNX Runtime CPU threads |
| `PORT` | `10000` (Docker image) | Port the container listens on |

## Run locally

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --port 8000
```

Then open `http://localhost:8000/docs`.

## Run with Docker

```bash
cd backend
docker build -t ser-api .
docker run --rm -p 8000:10000 ser-api
```

If `model/model.onnx` is not in the build folder, the Dockerfile downloads it from this repository's release assets.

## Deploy for free (Render)

Create a Render **web service** from the GitHub repository with **Docker** language, **Free** instance, **Root Directory = `backend`** and health check path `/health`. Every push to `main` redeploys automatically. Full guide: [../DEPLOY.md](../DEPLOY.md) and [docs/03-deployment](../docs/03-deployment/README.md).

## Limits to know

- Free instances **sleep after 15 minutes**; the first request may take about a minute.
- A free CPU needs several seconds per window, so a long clip takes longer.
- The endpoint is **open** (no authentication), which is fine for a demo.
- Audio is processed in memory and **never stored**.

## Test it

Import [`../postman/SER_API.postman_collection.json`](../postman/SER_API.postman_collection.json) into Postman or Insomnia and set the `baseUrl` variable to your server address. It covers success cases, silence, a bad file, a missing file and wrong methods.
